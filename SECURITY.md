# Security

The updater trusts the specific official GitHub repositories for ungoogled-chromium Windows releases, uBlock Origin, and Chromium Web Store. It queries Google Chrome Version History for the upstream Windows stable comparison and Google's Chrome Web Store update endpoint for locally approved extension IDs. Network requests use standard Windows/.NET TLS certificate validation, pinned host and initial artifact paths, explicit redirect hosts, byte limits and deadlines. Logs are local.

GitHub's release asset SHA-256 checks the bytes against repository-hosted metadata. An unsigned Windows asset has no independently verified Authenticode publisher. Installing one requires explicit acceptance for the exact tag and SHA-256. Signed installers require valid Authenticode and a configured signer pin. A compromised distribution account or build pipeline can affect release metadata and artifacts. Validate each browser release and compare its security patch level before approval.

Extension publisher identity is anchored to the signed CRX developer key and exact extension ID. Store packages additionally require the Chromium-pinned Google production proof. The permission comparison looks at API, host, optional, and content-script scope changes and selected security-related manifest fields. Review changes in publisher ownership, scripts, or behavior in the publisher's release material. A valid signature establishes control of the key and integrity of the CRX.

Configuration, state, downloads, logs, backups and installed code inherit a local access control list restricted to the Windows user and SYSTEM. A process running as that user can change these files. Keep the runtime on a local filesystem. The updater avoids following reparse points in profiles, backups and managed storage. Logs contain versions, extension IDs and operational messages with no launch arguments, profile names, or browser data. Backups contain private browser data, including extension storage and login-related files. Keep them private and use the same Windows account when restoring.

Supported signed extension installation and permission prompts stay inside Chromium. The launcher avoids editing protected preferences, force-install policies, default-app registry overrides, and developer-mode installation in production. The isolated runtime fixture loads verified extension contents in a disposable profile to exercise MV2 behavior. The fixture cannot establish production signed-install, migration or update success.

The updater delegates install and repair to the Chromium installer. The install lock coordinates launchers using this project. Direct launches and other installers remain external to the lock. A check against a broadly served Chrome version is an upstream patch-level indicator. Consider source differences and backports when judging CVE applicability.

Upstream Chromium and ungoogled-chromium Windows publish their own notices and license terms. uBlock Origin is GPL-3.0 and Chromium Web Store publishes MIT notices. This repository references and downloads their artifacts at runtime and includes no third-party binaries. Review each project's terms before redistributing them. This project has no selected license.
