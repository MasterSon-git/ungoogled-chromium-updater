# Security

The updater trusts the specific official GitHub repositories for ungoogled-chromium Windows releases, uBlock Origin, and Chromium Web Store. It queries Google Chrome Version History for the upstream Windows stable comparison and Google's Chrome Web Store update endpoint for locally approved extension IDs. Network requests use standard Windows/.NET TLS certificate validation, pinned host and initial artifact paths, explicit redirect hosts, byte limits and deadlines. Logs are local.

The example standing policy accepts unsigned Windows installers from the pinned official distribution. Both Automatic and Manual modes pin the release repository and initial asset URL, require the advertised byte count and SHA-256, and check the Windows executable version, architecture, and Authenticode status. GitHub-hosted hashes verify that the downloaded bytes match the hosted metadata. They cannot independently authenticate an unsigned publisher or protect against a compromised distribution account or build pipeline. A signed installer requires valid Authenticode and a configured certificate SHA-256 pin. An unsigned installer cannot satisfy a configured signer pin. Manual approval adds an exact tag and SHA-256 decision without changing these verification rules.

Extension publisher identity is anchored to the signed CRX developer key and exact extension ID. Store packages additionally require the Chromium-pinned Google production proof. The permission comparison looks at API, host, optional, and content-script scope changes and selected security-related manifest fields. Review changes in publisher ownership, scripts, or behavior in the publisher's release material. A valid signature establishes control of the key and integrity of the CRX.

Configuration, state, downloads, logs, backups and installed code inherit a local access control list restricted to the Windows user and SYSTEM. A process running as that user can change these files. Keep the runtime on a local filesystem. The updater avoids following reparse points in profiles, backups and managed storage. Logs contain versions, extension IDs and operational messages with no launch arguments, profile names, or browser data. Backups contain private browser data, including extension storage and login-related files. Keep them private and use the same Windows account when restoring.

Supported signed extension installation and permission prompts stay inside Chromium. The launcher avoids editing protected preferences, force-install policies, default-app registry overrides, and developer-mode installation in production. The updater extracts the verified installer's payload with the official 7-Zip executable under Program Files. Maintaining a current, trusted 7-Zip installation is a security requirement. The updater reports its version during extraction and the operator is responsible for keeping it current. Extraction requires the known full payload layout and applies archive size, entry and path limits. The installer itself never runs during the test. The latest stable signed full uBlock Origin CRX is verified against the pinned developer identity and official channel before its contents are loaded unpacked in a disposable profile.

The test keeps Chromium's sandbox enabled, directs test traffic to loopback, and uses local DevTools to probe and close the browser instance it started. Extraction and runtime have deadlines. A failed cleanup retains one workspace for manual attention. Only a successful result for the exact verified installer and CRX identities and test version is reused. The gate exercises request filtering for the tested version of full uBlock Origin. The launcher warns when an installed full uBlock Origin version differs. Native signed installation, permission prompts, update behavior, and compatibility with other MV2 extensions require independent validation.

The updater delegates install and repair to the Chromium installer and records a verified distribution revision after installation. During legacy migration it can also record the currently published revision when the existing approval, successful install log, Windows registration, and exact installed payload hashes agree. The migration check reads the installed files and never starts the installer. An unknown installed revision blocks same-Chromium-version installation. The install lock coordinates launchers using this project. Direct launches and other installers remain external to the lock. Chrome Version History is queried separately from release discovery and installation. A gap from broadly served Chrome stable indicates patch level. Consider differences in source and backports when judging CVE applicability.

Upstream Chromium and ungoogled-chromium Windows publish their own notices and license terms. uBlock Origin is GPL-3.0 and Chromium Web Store publishes MIT notices. This repository references and downloads their artifacts at runtime and includes no third-party binaries. Review each project's terms before redistributing them.
